## 4. 并发与死锁实测

`examples/concurrency_demo.exe` 现场输出（真实线程 + 真实会话）：

```
=== 场景 2：写锁互斥 —— A 未提交时 B 的写请求阻塞 ===
  [A] 已持 t1 的 X 锁并写入 v=11（未提交）
  等待中的加锁请求数: 1 ；B 是否已完成: 否（被阻塞）
  [A] COMMIT → 释放锁
  [B] 写完成: OK
  最终 t1.v = 22（B 后写，串行化正确）

=== 场景 3：交叉加锁形成死锁环，检测后选牺牲者回滚 ===
  [A] 持 t1 的 X 锁，[B] 持 t2 的 X 锁
  [A] 是否仍阻塞: 是
  等待图（txn -> 阻塞它的 txn）:
    10 -> 11   [X t2]
  [B] 反向请求返回: [DB-604] 检测到死锁，事务 txn=11 被选为牺牲者；等待环: 11 -> 10 -> 11
  累计死锁次数: 1
  [A] 最终返回 OK（拿到锁）
  B 的事务是否已结束: 是（已回滚）
  最终 t1.v = 100（B 对 t1 的写入已随回滚撤销）
```

## 6. 整合过程修复的既有缺陷

整合验证时发现并修复了 3 处**原有**缺陷（与本次新增功能无关，但会挡住「整体可测试」）：

| # | 位置 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- | --- |
| 1 | `cella_sql/tests/run_tests.ps1` | 直接运行脚本报大量解析错误 | 文件无 UTF-8 BOM，Windows PowerShell 5.1 按 ANSI 解码中文注释 | 补 BOM（内容不变） |
| 2 | `cella_sql/tests/sql/ok_query_1.sql` | 该用例必然失败（`-a -s -p` 退出码 1） | 建表列名 `nam` 与查询用的 `name` 不一致；末尾多了一条非法 `select ...` 语句（golden 里本来只有 2 条语句，且写的是 `name`） | 修正列名、删除非法尾句、按修正后输入重生成 golden |
| 3 | `cella_storage/CMakeLists.txt` | 聚合构建下 `test_examples` 2 个用例失败 | 示例路径用 `CMAKE_BINARY_DIR`（只在顶层工程时等于产物目录） | 改为 `CMAKE_CURRENT_BINARY_DIR`（独立构建行为不变） |

修复后：编译器 29/29、存储层 30/30（4620 断言）、整合层 86/86（740 断言）全绿。

## 7. 尚未覆盖 / 已知限制

| 项 | 说明 |
| --- | --- |
| 崩溃恢复 | 未做 ARIES/WAL 重放；`journal.log` 是审计轨迹。断电场景需人工核对（见 INTEGRATION.md 取舍 #8） |
| 行级锁 / MVCC | 表级 2PL；读会阻塞写，无快照隔离 |
| 压力测试 | 并发用例规模为 4 线程 × 12 轮；未做长稳与高并发基准 |
| 模糊测试 | 未引入 fuzz（编译器侧同样未覆盖，属原项目范围） |
| 死锁检测的饥饿性 | 牺牲者固定为「请求者」，极端交错下个别事务可能反复被牺牲；已用超时兜底 |
| 事务表回收 | `TxnManager` 保留已结束事务用于诊断，长跑进程需定期重启（见 INTEGRATION.md 取舍 #12） |
| 日期运算 | 日期族按文本存储，不支持日期加减 |
